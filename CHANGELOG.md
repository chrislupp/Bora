## [0.3.0] - 2026-11-25

### Added

- Corrected analysis, a port of AeroSandbox's `KulfanAirfoil.get_aero_from_neuralfoil`:
  `NeuralFoil::analyze_corrected(&CorrectedInput) -> CorrectedOutput` adds a Mach number
  (Prandtl-Glauert scaling, critical and drag-divergence Mach numbers, wave drag, buffet lift
  loss, supersonic lift slope, aerodynamic center shift), a post-stall model blended in beyond
  about 20 deg so that all 360 deg of angle of attack give sensible results
  (`include_360_deg_effects`), and control surface deflections (`ControlSurface`). The extra
  outputs are `cpmin`, `cpmin_0`, `mach_crit` and `mach_dd`. Matches AeroSandbox 4.2.10 to
  1e-6 relative over 88 reference cases (`tests/data/corrected_ref_data.h5`, generated by
  `scripts/generate_corrected_ref_data.py`)
- `NeuralFoil::analyze_corrected_with_gradients`: analytic gradients of the corrected outputs
  with respect to the 23 inputs and the Mach number (`CorrectedGradient`,
  `NUM_CORRECTED_INPUTS`, `input_index::MACH`) and with respect to each control surface
  deflection; and `NeuralFoil::analyze_corrected_batch` for many inputs at once
- Analysis from coordinates, matching NeuralFoil's `get_aero_from_airfoil`,
  `get_aero_from_coordinates` and `get_aero_from_dat_file`: `parse_dat` / `read_dat_file` read
  coordinate files, `normalize_coordinates` brings them to the unit-chord frame, and
  `FittedAirfoil` (`from_coordinates`, `from_dat_file`) with `NeuralFoil::analyze_airfoil`
  and `OperatingPoint` analyzes an airfoil with incidence, another chord or an offset, shifting
  the angle of attack, rescaling the Reynolds number and transferring the moment
- `KulfanParameters::max_thickness`
- `Error::Io` for unreadable coordinate files
- Philote discipline options `include_corrections` (adds the `mach` input and the `Cpmin`,
  `Cpmin_0`, `mach_crit`, `mach_dd` outputs, and applies the corrections) and
  `include_360_deg_effects`
- `compressible` example (`examples/compressible.rs`): a Mach sweep, a flap sweep and a sweep
  around the full circle of angle of attack
- Docs: "Mach number, stall and flaps" guide page; the geometry page covers coordinate files
  and airfoils that are not normalized

### Fixed

- Release workflow: the GitHub Release is now created with the `RELEASE_TOKEN` PAT (passed as
  the action's `token` input) instead of the default `GITHUB_TOKEN`, so publishing it triggers
  the crates.io publish workflow; 0.2.0 had to be published by a manual dispatch

## [0.2.0] - 2026-11-25

### Added

- `examples/openmdao/optimize_daedalus.py`: multipoint airfoil optimization (the NeuralFoil
  paper's human-powered-aircraft case) with OpenMDAO and IPOPT via pyOptSparse, using
  `bora_server` over Philote for the aerodynamics and analytic partials, with a step-by-step
  tutorial under Examples that lists the full scripts and whose figures (sections, polars along
  the flight schedule, IPOPT optimality and feasibility) are drawn from the script's `--json`
  output
- Docs: syntax highlighting in every code listing (including BibTeX), and the site name set in
  osifont, an ISO 3098 technical-drawing face

- `Network::evaluate_pair`: evaluates the network at two inputs in one traversal of the
  weights, bitwise identical to two `Network::evaluate` calls
- `cargo bench` timing harness (`benches/kernels.rs`, std only) for `NeuralFoil::analyze`,
  `NeuralFoil::analyze_with_gradients` and the network passes at every model size
- `NeuralFoil::analyze_scalars` and `NeuralFoil::analyze_scalars_with_gradients`, returning the
  new `AeroScalars` / `AeroScalarResult` (`AeroScalars` + `AeroScalarGradients`) types: the six
  scalar outputs without the boundary layer. Values are bitwise identical to `analyze`, and the
  gradients come from reverse-mode differentiation, matching `analyze_with_gradients` to
  rounding. On Apple M1 Pro, `analyze_scalars` is ~1.1-2.2x faster than `analyze` and
  `analyze_scalars_with_gradients` ~4-8x faster than `analyze_with_gradients`
- `Network::evaluate_first` (only the first `n` outputs) and
  `Network::evaluate_first_with_gradients` (those outputs plus their gradients with respect to the
  network inputs, by reverse-mode differentiation)
- Apache-2.0 license header with the public release statement (case number
  AFRL-2026-2087) and DoD disclaimers in every Rust source file and the README
- README citation section with BibTeX entries for the NeuralFoil paper and Peter Sharpe's
  PhD thesis
- `NeuralFoil::analyze_with_tangent` and `AeroTangent`: forward-mode Jacobian-vector product
  giving the directional derivative of every output (scalars and boundary layer arrays) along
  one direction in the 23-entry input space. On Apple M1 Pro it costs 1.8-2.0x `analyze`
  versus 11-13x for `analyze_with_gradients`; `output` is bitwise identical to `analyze`.
  Backed by the single-direction kernel `Network::evaluate_with_tangent` (runtime AVX2+FMA
  dispatch on x86-64 like the other passes)
- Batch analysis: `NeuralFoil::analyze_batch(&inputs) -> Vec<AeroOutput>` and the
  allocation-free `NeuralFoil::analyze_batch_into(&inputs, &mut outputs, &mut workspace)`, plus
  the scalar-only `NeuralFoil::analyze_scalars_batch` / `analyze_scalars_batch_into` returning
  `AeroScalars`. For a 64-point batch on Apple M1 Pro they are 1.9x (xxsmall) to 2.4x
  (xxxlarge) faster per point than a loop over `analyze`, and 2.1x to 2.5x faster than a loop
  over `analyze_scalars`; results match the single-point calls to within a few ulps
- Batched network kernel `Network::evaluate_batch` (feature-major `input_size() x n_points`
  in, `output_size() x n_points` out) with reusable `BatchWorkspace` scratch space: blocks of
  `BATCH_BLOCK_SIZE` (8) points are pushed through each weight matrix four output rows at a
  time with a vectorizable swish activation (runtime AVX2+FMA dispatch on x86-64), 2.7x
  (xxsmall) to 3.5x (xxxlarge) faster per point than `Network::evaluate`
- `polar` example (`examples/polar.rs`): sweeps the angle of attack at three Reynolds numbers
  and prints lift, drag, moment, transition locations, the analytic lift-curve slope and the
  analysis confidence; `--json` writes the outline and sweeps for plotting
- Documentation: new overview, airfoil geometry, inputs and outputs, gradients, analysis
  confidence, network sizes, weights and deployment, Philote discipline, "How NeuralFoil
  works", accuracy and limits, polar sweep and references pages, with the NeuralFoil paper and
  documentation cited where they are drawn on
- `publish.yml` workflow: publishes each stable release to crates.io with trusted publishing
  (pre-releases are skipped; the first publish uses a temporary `CARGO_REGISTRY_TOKEN` secret)

### Changed

- The package is named `bora-foil` (`bora` is taken on crates.io); the library is still
  imported as `bora`. The published crate leaves out `docs/`, `.github/`, `scripts/` and
  `CLAUDE.md`
- Faster network kernels: 16-accumulator dot products, a register-accumulated forward-mode
  Jacobian kernel (seed counts up to 32 padded to a multiple of 4), one sigmoid evaluation per
  neuron for swish and its derivative, and one buffer allocation per pass instead of one per
  layer. On Apple M1 Pro, `Network::evaluate` is ~1.2-1.7x and `Network::evaluate_with_jacobian`
  ~2.1-2.3x faster; results differ from 0.1.0 in the last bits because the summation order
  changed
- `NeuralFoil::analyze` evaluates the original and alpha-flipped inputs with
  `Network::evaluate_pair` (~1.3-2.4x faster end to end); `NeuralFoil::analyze_with_gradients`
  is ~2.0-2.3x faster from the Jacobian kernel
- `Network::evaluate_with_jacobian` accepts `n_seed = 0` (computing only the values) instead
  of panicking
- When `include_boundary_layer` is false, the Philote discipline's `compute` uses
  `NeuralFoil::analyze_scalars` (same outputs, bitwise) and `compute_partials` uses the
  reverse-mode `NeuralFoil::analyze_scalars_with_gradients` (partials agree with the
  forward-mode ones to rounding, ~1e-13 relative)
- `examples/optimize_airfoil.rs` uses `NeuralFoil::analyze_scalars_with_gradients`
- Documentation site rewritten and redesigned: content reorganized into getting started,
  guide, background, examples and references; figures are drawn from Bora's own output
  (`docs/src/data/polar.json`, generated by the `polar` example) on a ruled graph sheet, with
  a section-characteristics plate on the home page; fonts are self-hosted
- Documentation timings now cover all eight network sizes
- On x86-64, the network passes detect AVX2 and FMA at run time (once per process) and use
  them when available, so default builds (including dependents from crates.io) no longer need
  `RUSTFLAGS="-C target-cpu=native"` for FMA and 256-bit vectors; CPUs without them use the
  SSE2 baseline, and builds with AVX2/FMA enabled statically skip the check. Results with and
  without FMA differ in the last bits. aarch64 is unchanged

### Removed

- `examples/optimize_airfoil.rs` (single-point Adam/penalty optimization) and its docs page;
  `examples/openmdao/optimize_daedalus.py` replaces it

### Fixed

- Documentation site: math was not typeset because the KaTeX stylesheet was loaded from a CDN
  with an incorrect integrity hash, which browsers reject; the stylesheet and its fonts are now
  bundled from the installed `katex` package

## [0.1.0] - 2026-09-19

### Added

- Rust port of [NeuralFoil](https://github.com/peterdsharpe/NeuralFoil) 0.3.3: `bora::NeuralFoil`
  predicts CL, CD, CM, transition locations, analysis confidence, and boundary layer
  distributions (theta, H, ue/vinf at 32 stations per surface) from Kulfan (CST) parameters
  and operating conditions, for all eight upstream model sizes
- Analytic gradients of every output with respect to all 23 inputs (16 CST weights, leading
  edge weight, TE thickness, alpha, Re, n_crit, xtr_upper, xtr_lower) via forward-mode
  differentiation through the network, for gradient-based optimization
- Kulfan (CST) geometry utilities: coordinate generation and least-squares parameter fitting
  from coordinates (`bora::generate_kulfan_coordinates`, `bora::fit_kulfan_parameters`)
- HDF5 weight format (`data/nn-*.h5`, `data/scaled_input_distribution.h5`) with converter
  script (`scripts/convert_weights.py`); weight directory resolution via explicit path,
  `BORA_DATA_DIR`, or the source-tree `data/` directory; `Network::from_bytes` and
  `InputDistribution::from_bytes` for embedded weights
- Reference-value test suite (64 cases generated from Python NeuralFoil via
  `scripts/generate_output_ref_data.py`) and finite-difference verification of all gradients
- Reference-gradient test suite: analytic gradients verified directly against Python
  NeuralFoil jacobians computed with CasADi (`scripts/generate_gradient_ref_data.py`)
- Test reference data is committed as HDF5 files (`tests/data/output_ref_data.h5`,
  `tests/data/gradient_ref_data.h5`) loaded at test runtime via a shared loader
  (`tests/common/mod.rs`); regenerate only when updating the reference data
- Examples: basic analysis with gradients (`example`) and gradient-based airfoil drag
  optimization at fixed lift with Adam (`optimize_airfoil`)
- Philote discipline (`bora::philote::BoraDiscipline`, behind the `philote` Cargo feature):
  exposes NeuralFoil function and analytic gradient evaluations over gRPC via `philote-mdo`,
  with `model_size`, `data_directory`, and `include_boundary_layer` options, plus a standalone
  `bora_server` executable
- Docusaurus documentation site with custom theme, KaTeX math support, and versioned docs
- GitHub Actions workflow for automatic documentation deployment to GitHub Pages
- Docs versioning integrated into the release workflow
- Apache-2.0 license (`LICENSE`) and a `NOTICE` file reproducing the MIT license notices of
  NeuralFoil (ported code and network weights) and AeroSandbox (Kulfan geometry)

### Changed

- Ported the library from C++20/CMake to a Rust crate (edition 2024, MSRV 1.89) with an
  idiomatic API (`snake_case` fields, `Result`-returning constructors, `ModelSize` parsing
  via `FromStr`); outputs are unchanged and the network kernels are as fast as or faster than
  the C++ implementation
- HDF5 files are read with the pure-Rust `hdf5-pure` crate: the system HDF5 library is no
  longer required, and the Philote build no longer needs a system gRPC/protobuf install
- CI now checks `cargo fmt` and `cargo clippy`, builds and tests on Ubuntu and macOS with
  stable Rust and the MSRV, and runs the Philote tests; the release workflow bumps the
  version in `Cargo.toml`
- CI workflows use the current Node 24-based major versions of all GitHub Actions (dropping
  the deprecated Node 20 runtime and the `FORCE_JAVASCRIPT_ACTIONS_TO_NODE24` workaround),
  and the documentation builds on Node 24 LTS
- Documentation site upgraded to Docusaurus 3.10.2 with the `@docusaurus/faster` (Rspack)
  bundler, fixing production builds broken by webpack 5.106+; `docs/package-lock.json` is now
  committed so the docs workflow's `npm ci` works
